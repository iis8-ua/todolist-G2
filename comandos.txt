======================================================================
 1. APP EN LOCAL CON H2
======================================================================

    ./mvnw spring-boot:run

======================================================================
 2. APP EN LOCAL CON POSTGRESQL (perfil postgres)
======================================================================

2.1. Usar la base de datos que ya tienes

    docker start db-equipo02
    docker exec db-equipo02 pg_isready -U mads

2.2. Si NO existe el contenedor de BD, crearlo
    docker network create network-equipo02 2>/dev/null || true

    docker run -d \
        --name db-equipo02 \
        --network network-equipo02 \
        --network-alias postgres \
        -p 5432:5432 \
        -v "$PWD":/mi-host \
        -e POSTGRES_USER=mads \
        -e POSTGRES_PASSWORD=mads \
        -e POSTGRES_DB=mads \
        postgres:13

2.3. Lanzar la aplicacion con el perfil postgres

    ./mvnw spring-boot:run -Dspring-boot.run.profiles=postgres

2.4. Comprobar que la BD funciona

    docker exec -it db-equipo02 psql -U mads -d mads

    # Dentro de psql:
    #   \l                  -> lista de bases de datos
    #   \dt                 -> lista de tablas
    #   \d equipos          -> estructura de la tabla equipos
    #   SELECT * FROM usuarios;
    #   \q                  -> salir


======================================================================
 3. PERFIL DE PRODUCCION (postgres-prod, ddl-auto=validate)
======================================================================

En produccion la app NO crea ni modifica tablas: solo valida el esquema.
La BD debe tener ya el esquema y los datos.

3.1. Cargar el esquema en una BD vacia:

    docker exec db-equipo02 psql -U mads -d mads -f /mi-host/sql/schema-1.2.0.sql

3.2. O restaurar una copia de seguridad completa

    docker exec db-equipo02 sh -c 'psql -U mads -d mads < /mi-host/sql/backup03112026.sql'

3.3. Lanzar la app en local con validacion del esquema:

    ./mvnw spring-boot:run -Dspring-boot.run.profiles=postgres-prod

======================================================================
 4. DESPLIEGUE EN PRODUCCION CON DOS CONTENEDORES
======================================================================

4.1. Crear la red:

    docker network create network-equipo02

4.2. Conectar el contenedor de BD a esa red con el alias "postgres".
     Asi la app lo encuentra en postgres:5432 sin recrear la BD:

    docker network connect --alias postgres network-equipo02 db-equipo02

4.3. Alternativa: recrear la BD desde cero

    docker rm -f db-equipo02

    docker run -d \
        --name db-equipo02 \
        --network network-equipo02 \
        --network-alias postgres \
        -v "$PWD":/mi-host \
        -e POSTGRES_USER=mads \
        -e POSTGRES_PASSWORD=mads \
        -e POSTGRES_DB=mads \
        postgres:13

    docker exec db-equipo02 sh -c 'psql -U mads -d mads < /mi-host/sql/backup03112026.sql'

4.4. Construir y publicar la imagen de la aplicacion:

    ./mvnw clean package

    docker build -t israelizqdo9/mads-todolist-equipo02:1.3.0-snapshot .

    docker login
    docker push israelizqdo9/mads-todolist-equipo02:1.3.0-snapshot

4.5. Lanzar la aplicacion en produccion:

    docker rm -f mads-todolist 2>/dev/null || true

    docker run -d \
        --name mads-todolist \
        --network network-equipo02 \
        -p 8080:8080 \
        israelizqdo9/mads-todolist-equipo02:1.3.0-snapshot \
        --spring.profiles.active=postgres-prod \
        --POSTGRES_HOST=postgres
